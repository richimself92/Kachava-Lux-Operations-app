# comment-translation Specification

## Purpose
Lets every user read a request's user-typed text (description, notes, pending/reopen reasons, completion notes) in the language selected with the ESP|ENG switch, through machine translation that never replaces the original.

## Requirements

### Requirement: Translatable comments
The following user-typed text of a request SHALL be translatable: the description, the supervisor completion notes, and the details of audit entries for notes and status changes. Text generated by the system (creation, reassignment, photo and detail-edit entries) SHALL keep its existing dictionary-based rendering and SHALL NOT be sent for machine translation.

#### Scenario: Note translated
- **WHEN** the app is set to English and a request has a note written in Spanish
- **THEN** the note is shown in English

#### Scenario: System entry not machine-translated
- **WHEN** the app is set to Spanish and the audit history shows a "Reassigned" entry
- **THEN** it is rendered from the app's dictionary and no translation request is made for it

### Requirement: Comments follow the language switch
Switching ESP|ENG SHALL keep translating the app's fixed labels exactly as before and SHALL also show each translatable comment in the selected language (`es` or `en`). A comment already in the selected language SHALL be shown as written, without a machine-translation label.

#### Scenario: Switch to English
- **WHEN** a supervisor viewing a request with a Spanish description switches to ENG
- **THEN** the labels change to English and the description is shown translated into English

#### Scenario: Already in the selected language
- **WHEN** the app is set to Spanish and a note was written in Spanish
- **THEN** the note is shown as written with no machine-translation label

### Requirement: Machine translations are labelled and reversible
Every comment shown as a translation SHALL carry a visible "Machine translation" / "Traducción automática" label and a per-comment control to show the original text and switch back to the translation.

#### Scenario: View original
- **WHEN** a user clicks "View original" on a translated note
- **THEN** that note shows its original text, the other comments stay translated, and the control offers to show the translation again

### Requirement: Loading and failure states
While a comment is being translated, the original SHALL stay visible with a loading indicator. If its translation fails, the original SHALL stay visible with a clear message that it could not be translated. A failure SHALL NOT block other comments or any other action on the request.

#### Scenario: Translation service unavailable
- **WHEN** the translation service returns an error for a request's comments
- **THEN** each affected comment shows its original text and a "Could not translate" message, and the user can still change the status and add notes

### Requirement: No duplicate translation requests
The app SHALL NOT issue a second translation request for a comment and target language while one is in progress or after it has succeeded in the current session, including when the user toggles the language switch repeatedly.

#### Scenario: Rapid toggling
- **WHEN** a user switches ESP → ENG → ESP → ENG while the English translation is still loading
- **THEN** only one translation request for English is made, and its result is shown when it arrives

### Requirement: Originals are the source of truth
Machine translation SHALL NOT modify, replace or delete the stored original text of any comment, and translated text SHALL NOT be written into requests or audit entries.

#### Scenario: Original unchanged after translation
- **WHEN** a note is translated into English and later viewed in Spanish
- **THEN** the stored note is byte-for-byte identical to what the author wrote

### Requirement: Authenticated and authorized translation endpoint
The translation endpoint SHALL accept only signed-in users who pass the app's access rules (Microsoft company account, active on the allowlist) and SHALL translate a request's comments only for users allowed to read that request (its submitter, supervisors and admins). It SHALL accept references to comments, not free text, and read the originals from the backend.

#### Scenario: Unauthenticated call
- **WHEN** the endpoint is called without a valid sign-in token
- **THEN** it rejects the call as unauthenticated and nothing is translated

#### Scenario: Staff asks for another user's request
- **WHEN** a staff user requests translations for a request they did not submit
- **THEN** the call is rejected and no text is returned

#### Scenario: Deactivated user
- **WHEN** a user who has been deactivated calls the endpoint
- **THEN** the call is rejected

### Requirement: Request validation
The endpoint SHALL reject a call whose target language is not `es` or `en`, whose comment references are malformed or point to non-translatable entries, that asks for more than 50 comments, or whose combined original text exceeds 30,000 characters.

#### Scenario: Unsupported target language
- **WHEN** the endpoint is called with target `fr`
- **THEN** it rejects the call as an invalid argument

#### Scenario: Too many comments
- **WHEN** the endpoint is called with 51 comment references
- **THEN** it rejects the call as an invalid argument

### Requirement: Source language handling
When a comment's source language is known from an earlier translation, the backend SHALL send it as the source language. Otherwise it SHALL let the translation service detect it. The response SHALL include, per comment, the translated text (or an indication that it is already in the target language) and the detected source language when available.

#### Scenario: First translation detects the language
- **WHEN** a Spanish note is translated for the first time
- **THEN** the response reports source language `es`, and later translations of that note send `es` as the source

### Requirement: Translation cache
Each successful result SHALL be stored keyed by the comment, the target language and a fingerprint of the original text. A later request for the same comment and target with an unchanged original SHALL be answered from the cache without calling the translation service. A changed original SHALL be translated again. Clients SHALL NOT be able to read or write the cache directly.

#### Scenario: Repeat view served from cache
- **WHEN** two supervisors open the same request in English one after the other
- **THEN** the translation service is called only for the first

#### Scenario: Edited text invalidates cache
- **WHEN** the description of a request is edited after it was translated
- **THEN** the next view in the other language shows a translation of the new description

#### Scenario: Direct cache access denied
- **WHEN** a signed-in user tries to read or write a cached translation directly
- **THEN** the backend rejects it

### Requirement: Translation errors are reported, not hidden
When the translation service fails or its quota is exhausted, the endpoint SHALL return an error the app can show (distinguishing "try again later" from other failures). It SHALL leave originals and existing cache entries untouched.

#### Scenario: Quota exhausted
- **WHEN** the translation service reports its quota is exhausted
- **THEN** the endpoint returns a "resource exhausted" error and the app shows the originals with a try-later message

### Requirement: Privacy of comment text
Comment text, original or translated, SHALL NOT be written to logs. Logs for translation requests SHALL contain only technical metadata such as target language, number of comments, cache hits, duration and outcome.

#### Scenario: Logged request
- **WHEN** a translation request completes or fails
- **THEN** its log entry contains the target language, counts, duration and outcome, and no comment text

### Requirement: No credentials in the client or repository
The translation service SHALL be called only from the backend, authenticated as the backend's service identity. No API key, service-account key or other translation credential SHALL be shipped in the web app or committed to the repository.

#### Scenario: Built bundle inspected
- **WHEN** the production web bundle and the repository are searched for translation credentials
- **THEN** none are found
